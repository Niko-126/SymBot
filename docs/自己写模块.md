# 自己写模块

> 给想给内核加功能、但不想动主代码的人。读完你能独立写一个外置模块：加工具、加接口、挂钩子，落地就能用。
> 不需要看懂内核。模块只跟一个 `register(api)` 打交道。
> 全程不碰 `app/` 里的任何文件，升级也不会把你的东西冲掉。

---

## 一、模块是什么

一个目录，两个文件：

```text
modules/hello/
├── manifest.json     清单：我叫什么、入口在哪、需要什么依赖
└── hello.py          入口：在里面挂工具、挂路由、挂钩子
```

就这么点。目录放进 `modules/`，重启内核，或者在面板「控制台 → 服务 → 模块」点一下「重新加载」，它就在了。目录里没有 `manifest.json` 的文件夹，内核当没看见，不会崩。

**为什么用这种形式**：模块是代码，不是数据。它跟你换不换数据目录无关，也跟内核内部怎么实现无关。内核只认两件事——清单合法、入口里有 `register(api)`。剩下的它不管。

一句话类比：好比给手机装个小工具，插上就能用，不用拆主板。

## 二、最小可跑例子

### 2.1 建目录

```text
modules/hello/
```

目录名必须和清单里的 `id` 一模一样，只许小写字母、数字、连字符。

### 2.2 写 `manifest.json`

```json
{
  "id": "hello",
  "name": "示例模块 · 你好",
  "version": "1.0.0",
  "entry": "hello.py",
  "kind": "tool",
  "requires": []
}
```

### 2.3 写 `hello.py`

```python
def hello_ping() -> dict:
    return {"ok": True, "pong": 1700000000.0}


def register(api):
    api.register_tool("hello_ping", hello_ping, desc="示例工具：回一个 pong")
```

### 2.4 生效

重启内核，或者面板「控制台」→ 右上「服务」→ 模块这一栏 →「重新加载」。

`register(api)` 只在加载时调用一次。模块顶层代码在 import 时执行，所以**别在顶层读大文件、别联网、别起线程**——那会让启动变慢，而且出错了很难看出是哪个模块。

### 2.5 `api` 上有什么

| 成员 | 怎么用 | 说明 |
|---|---|---|
| `api.register_tool(name, fn, desc="")` | `api.register_tool("hello_ping", hello_ping)` | 注册工具。`fn(**args)` 返回 dict，名字全局唯一，先到先得 |
| `api.register_router(router)` | `api.register_router(router)` | 挂一个 `fastapi.APIRouter`，重新加载时自动摘挂 |
| `api.register_hook(event, fn)` | `api.register_hook("modules.loaded", fn)` | 挂钩子。`fn(payload: dict)`，事件名自己定 |
| `api.dir` | `api.dir / "template.txt"` | 你自己这个模块目录的 `pathlib.Path` |
| `api.log` | `api.log.info("...")` | 现成的 logger，别自己再配一套 |

事件名不预设。内核在合适的位置触发，你只管挂。想跟另一个模块约事件名，你俩自己约。

## 三、manifest 六个字段

| 字段 | 必填 | 怎么填 |
|---|---|---|
| `id` | 是 | 模块标识。小写字母、数字、连字符，**必须等于目录名** |
| `name` | 是 | 面板上显示的名字，中文随便写 |
| `version` | 是 | 版本号，`1.0.0` 这种 |
| `entry` | 是 | 入口文件的相对路径，相对模块目录，不许用 `..` 跳出去 |
| `kind` | 是 | `tool` / `route` / `hook` / `mixed` |
| `requires` | 是 | pip 包名列表。**只校验，不代装**。没依赖写 `[]` |

填错会报什么，照着这条表对：

| 字段 | 报错长这样 |
|---|---|
| `id` | `id 不合法：Hello（只能小写字母、数字和连字符，例：hello-world）` |
| `id` | `id 与目录名不一致（目录名必须是模块 id）` |
| `name` | `name 必须是非空字符串` |
| `version` | `version 必须是非空字符串（例：1.0.0）` |
| `kind` | `kind 只能是 tool / route / hook / mixed` |
| `entry` | `entry 不许往上跳（只能指向模块目录里的文件）` |
| `entry` | `entry 文件不存在` |
| `requires` | `缺依赖：requests（pip install requests；内核不自动装）` |

几个细节，知道了能少踩坑：

- 清单按 `utf-8-sig` 读，记事本存出来的 BOM 也认。
- `entry` 里的反斜杠会先归一成 `/`，在 Windows 上手写路径不至于报错。
- 没有清单的文件夹直接跳过；`.` 和 `_` 开头的目录也跳过。`__pycache__` 和半成品空目录不会刷屏。
- 同时错好几个字段时，面板只列前几条，后面用省略号。
- `author`、`description`、`homepage` 这类额外字段随便加，不校验。
- `kind` 只是声明，用来分类。`tool` 模块顺带挂个路由也能跑。
- `requires` 查依赖看两条：发行名和 import 名。所以 `PyYAML` 和 `yaml` 两种写法都认。

## 四、三种类型

`kind` 决定这个模块是干什么的。它不强制拦截，只影响你怎么写、别人怎么理解。

| 类型 | 适用场景 | 你得到的东西 |
|---|---|---|
| `tool` | 让模型能调用一个动作：算个数、查个天气、读本地笔记 | 一个注册进工具环的函数 |
| `route` | 让面板或外部程序能调一个接口：查状态、传文件、写配置 | 一组 `/v1/modules/<id>/...` 的 HTTP 接口 |
| `hook` | 在某件事发生时插一脚：启动后预热、每轮对话后记账 | 不对外暴露，只在事件点被调用 |
| `mixed` | 上面几种都要 | 混合，按需挂 |

### 4.1 tool：给模型一个动作

```python
def word_count(text: str = "") -> dict:
    return {"chars": len(text), "words": len(text.split())}


def register(api):
    api.register_tool("word_count", word_count, desc="数一段文字有几个字、几个词")
```

工具收到的是关键字参数，返回 dict。名字全局唯一——撞了的话，后加载的模块整体加载失败，面板会写清是被谁占了。

### 4.2 route：给自己开个接口

```python
from fastapi import APIRouter

router = APIRouter()


@router.get("/status")
def status() -> dict:
    return {"ok": True, "state": "running"}


def register(api):
    api.register_router(router)
```

路由自带前缀 `/v1/modules/<id>/`，所以上面那个接口实际是 `/v1/modules/hello/status`。不带前缀也能跑，但早晚和别人撞，别图省事。

### 4.3 hook：在事件点上插一脚

```python
def on_loaded(payload: dict) -> None:
    print("模块装好了：", payload)


def register(api):
    api.register_hook("modules.loaded", on_loaded)
```

钩子的返回值没人看，做副作用就行。别在里面做耗时操作——它在主链上。

## 五、装、停、重载、在线安装

### 5.1 手动装

1. 拿到模块目录或者压缩包。
2. 解压，让 `modules/<id>/manifest.json` 直接躺在那儿。**多套一层是最常见的放错**（变成 `modules/x/hello/manifest.json`）。
3. 面板「控制台」→「服务」→ 模块这一栏 →「重新加载」。

不想开面板的话：

```powershell
python -m app.core.modules --init   # 建 modules/ 和说明文件
python -m app.core.modules --list   # 打印模块清单（JSON）
```

### 5.2 停用与卸载

**停用**：模块列表里每一行都有一个开关，点一下就关。工具和路由当场下架，文件一个都不动。再点开立刻回来。

开关状态记在配置里，空着当启用——所以装进来就能用，不用先去点开。

**卸载**：

1. 关开关（可选，但能让工具马上消失）。
2. 删掉 `modules/<id>/` 整个目录。
3. 点「重新加载」。

残留的开关不影响运行。同一个 id 再装回来，会沿用上次的状态。想回到「装进来就启用」，把那个开关删掉再重载。

### 5.3 在线安装

模块那一栏有一个输入框，贴进去点「下载安装」：

| 你贴什么 | 会下什么 |
|---|---|
| `owner/repo` | 这个仓库 main 分支的整包 |
| `https://github.com/owner/repo` | 同上，自动转换 |
| `https://github.com/owner/repo/tree/分支名` | 指定分支 |
| `https://.../xxx.zip` | 直链，直接下 |

示例仓库：<https://github.com/Niko-126/SymBot>，里面的 `modules/` 目录有可以照着抄的写法。

**关键一点**：下载的是整个仓库压缩包，所以清单必须在包根，或者包里只有一层目录。仓库根目录结构复杂、清单又埋在两三层下，会报「包里找不到 manifest.json」。自己发模块的话，一个仓库只放一个模块，最省事。

分支写成 `main` 结果 404 时，内核会自动再试一次 `master`，不用你自己改。

装的时候内核会做几件事：校验是 https → 下载到内存并卡体积 → 防目录穿越地解压 → 找清单、校验 id 与入口 → 同盘原子移动到位。目标目录已存在时，要显式勾「覆盖」，并且**先把旧目录整个搬到 `modules/.backup/` 里**，再放新的。搬坏了还能捞回来。

面板背后就是三个接口：

```text
GET  /v1/console/modules
POST /v1/console/modules/{module_id}/toggle    body {"enabled": true}
POST /v1/console/modules/reload
```

配了控制台令牌就要带 `X-Console-Token` 或 `?token=`。

## 六、装载顺序为什么重要

面板是挂在 `/` 上的静态目录。框架按注册顺序匹配路径：**谁先注册谁先拿请求**。静态挂载一旦排到前面，后面所有接口都会被它当文件找，找不到就是 404。

所以顺序只能是：

```python
app.include_router(内置路由)      # 1. 先挂所有内置路由
modules_mod.attach(app)          # 2. 再挂外置模块（运行时才知道有哪些）
app.mount("/", StaticFiles(...)) # 3. 最后挂面板静态目录
```

`attach` 而不是 `include_router`，是因为模块路由要等加载完才知道长什么样。它顺便把启动时的加载也做了。

**症状对照**：新接口在浏览器里 404，在 `curl` 里也 404，但代码明明写了——八成是顺序反了，或者被前一个 handler 抢先匹配了。

## 七、安全边界

模块代码跑在**内核进程里**，权限和内核一样：能读任意文件、能发网络请求、能写数据库、能改 `sys.modules`。

所以内核在安装这一关上守得比较死：

| 关卡 | 规矩 |
|---|---|
| 来源 | 只认 `https`。本机 `127.0.0.1` / `localhost` 的 http 放开，给离线自测用 |
| 体积 | 压缩包 40 MB 上限，解压后 200 MB 上限，成员数 4000 上限 |
| 路径 | 绝对路径、`..`、越界成员一律拒；解压后逐个校验落点 |
| 覆盖 | 目标已存在时必须显式确认；覆盖前把旧目录整个备份到 `modules/.backup/` |
| 依赖 | `requires` 只校验，绝不自作主张 `pip install`——装包本身就是执行别人的代码 |
| 回滚 | 注册到一半炸了会整体回滚，不留半截工具在那儿 |

这些挡的是「手滑」和「来路不明的压缩包」，挡不住「你自己写了一段坏代码」。所以：

- 只装你看得懂、信得过的模块；
- 模块只能在 `register(api)` 里挂东西，改不了内核；
- 出事就停用、再删目录，不用重启也不用改代码。

## 八、调试与常见报错

排错先看模块列表：每一行都带 `error`（人话）、`loaded`、`tools`、`routes`、`hooks`。有 `error` 就先读它。

| 现象 | 为什么 | 怎么办 |
|---|---|---|
| 面板里根本看不到模块 | 压缩包多套了一层，清单不在 `modules/<id>/` 根上 | 把内层目录提出来，让 `manifest.json` 直接存在 |
| `id 与目录名不一致` | 文件夹叫 `Hello-1`，清单写 `hello` | 改成一致，只许小写、数字、连字符 |
| `缺依赖：xxx` | `requires` 里的包没装 | 自己 `pip install xxx`，内核不代装 |
| `entry 文件不存在` | 路径写错，或者只传了清单没传代码 | 对照目录里的真实文件名 |
| `entry 不许往上跳` | 用了 `../` | 只指模块目录里的文件 |
| `语法错误 xxx.py:12` | 代码本身写错了 | 按行号改，改完点「重新加载」 |
| 报错说入口没有 `register` | 忘了写 `def register(api)` | 补上，它是唯一的入口约定 |
| 工具撞名，模块整体加载失败 | 别人先注册了同名工具 | 改名，或者先停用占位的那个再重载 |
| 接口 404 | 没注册 router，或模块已停用，或路径前缀写错 | 看面板的 `routes` 列表和实际前缀 |
| 停用了工具还能用 | 只改了开关没重载 | 走面板开关（会自动重载），或调一次 reload |
| 启动明显变慢 | 模块顶层在干重活 | 把活挪进工具函数里，别放 import 期 |

改完代码点「重新加载」会重新 import，整个模块包从内存里摘掉重来，不会拿到旧对象。模块内部可以用相对导入（`from .helper import x`），重新加载时也是新的。

后台任务自己起，然后在模块说明里写清楚它什么时候退出——不然内核关了它还在跑，下次启动就两份。
