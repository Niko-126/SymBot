# 常见坑

> 给改代码、打包、发版的人。这些都是真机上撞出来的，不是推演。
> 每条统一三行：现象、为什么、怎么办。照着对症状，能省半天。
> 看完你应该能在十分钟内判断：是环境、数据、前端、打包，还是发布环节出的问题。

---

## 怎么用这篇

先看现象，别先看结论。同一个「起不来」，可能是端口被占，也可能是数据库半拷。

| 你撞到的 | 去第几节 |
|---|---|
| 装不上依赖、起不来、端口冲突、路径报错 | 一、环境类 |
| 数据没了、库打不开、备份白拷了 | 二、数据库类 |
| 页面空白、改了没反应、接口 404 | 三、前端类 |
| 装完起不来、包变小了、版本号报错 | 四、打包类 |
| 发出去才发现带了自己的号 | 五、发布类 |

## 一、环境类坑

### 1.1 Python 版本太新，装依赖卡在编译

**现象**：`pip install -r requirements.txt` 跑到某个包开始编译，报缺少编译器，或者干脆没有轮子（wheel）。

**为什么**：新版 Python 刚发布时，生态里的二进制包往往还没跟上。源码编译要 C 工具链，Windows 上默认没有。

**怎么办**：用 Python 3.11 建虚拟环境。它最稳；更新的版本不一定有现成轮子，装之前先拿一个小包试一下。

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

装完先确认解释器是虚拟环境里那个，别糊里糊涂装到全局去了。

### 1.2 端口被占，启动直接退出

**现象**：启动命令一闪而过，日志里一行 `address already in use`，或者面板打不开但进程确实在。

**为什么**：上一次的内核没退干净（关窗只是收进托盘），或者别的程序占了同一个端口。

**怎么办**：

```powershell
Get-NetTCPConnection -LocalPort 8000 -State Listen | Select-Object OwningProcess
Get-Process -Id <上面的进程号>
```

确认是自己人，就结束它；不确定就换个端口：

```powershell
.\.venv\Scripts\python.exe -m app.cli serve --port 8787
```

**注意**：换端口之后，面板地址、桌面壳里写的地址、你自己 `curl` 的地址都要跟着换。只改一处，症状会变成「内核起来了但面板连不上」。

### 1.3 路径带空格或中文，脚本报「找不到文件」

**现象**：`'C:\Program Files\My' 不是内部或外部命令`，或者 bat 跑到一半停住。

**为什么**：路径没加引号。空格把一条命令切成了两段，中文路径还可能在非 UTF-8 的控制台里变成乱码。

**怎么办**：

- 命令行里所有路径都加引号：`& "C:\Program Files\My Bot\.venv\Scripts\python.exe"`；
- 脚本里用变量拼路径时，调用处统一用引号包起来；
- 能换目录就换到没有空格、纯英文的路径下，省一半事。

### 1.4 本机 shell 带着 `ELECTRON_RUN_AS_NODE=1`

**现象**：桌面壳的 exe 双击秒退，日志里什么都没有。命令行里跑却正常。

**为什么**：这个环境变量会让 Electron 以纯 Node 模式启动，不加载窗口，跑完就退。

**怎么办**：测试前先清掉这个变量。

```powershell
Remove-Item Env:ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
```

### 1.5 系统代理指向死端口，连本地都连不上

**现象**：Clash 之类退了，访问 `127.0.0.1` 也超时；日志里是连接被拒。

**为什么**：HTTP 客户端默认读系统代理设置，注册表里那条代理还留着，本地请求也被塞进了死代理。

**怎么办**：所有打本地服务的客户端一律关掉代理继承（初始化客户端时传 `trust_env=False`）。已经这么写了的地方别改回去。

pip 被同一个代理卡住时：

```powershell
pip install --proxy "" --index-url https://pypi.org/simple
```

`Invoke-WebRequest` 调试时加 `-NoProxy`。

## 二、数据库类坑

### 2.1 跑着的时候拷数据库，拷出来是坏的

**现象**：备份了一个 `life.db`，恢复之后有一部分对话不见了，或者库直接打不开。

**为什么**：数据库开着 WAL 模式。新写入先落在旁边的日志文件里，主库文件可能是「旧的」。只拷 `.db` 一个文件，等于拷了一份过期快照，还可能撕在半个事务上。

**怎么办**：

1. **先关程序**，等进程真的退出（托盘图标消失、任务管理器里没有）。
2. 整个 `data/` 目录一起复制，不要只挑文件。
3. 非要热拷，就把同目录下的 `.db`、`-wal`、`-shm` 三个一起拷，并且三个来自同一时刻。

宁可多等十秒，别拷出一个「看起来能用」的备份。

### 2.2 手改 `life.db`，改完她开始说胡话

**现象**：用第三方工具打开数据库改了几行，重启之后关系错乱、记忆对不上、或者直接报错。

**为什么**：这张库不是一张平表。写入有唯一的入口，入口里还会顺手做几件别的事（补时间、维护关联）。你从外面写进去的行，缺了这些附带动作，读到的人就懵了。

**怎么办**：

- 想改记忆：走面板，能看、能改、能删、能钉。
- 想改关系：走面板或者开发接口，别直接改库。
- 已经改坏了：停程序，用备份覆盖回去。没有备份就发邮件求助，别在坏库上继续改。

### 2.3 数据目录被拼了两层

**现象**：程序能起，但面板里空空如也，像刚装的一样。翻目录发现 `data/data/life.db`。

**为什么**：配置里的库路径本身已经带了 `data/` 前缀，数据根又指到了 `data/` 上，结果叠了一层。

**怎么办**：数据根指到**程序所在目录**，不要指到 `data/`。改完重启，确认只有一层 `data/`。

### 2.4 干净仓库里某项测试总是 SKIP

**现象**：`fullcheck` 比别人少一项，提示 `sticker-file` 跳过。

**为什么**：干净仓库里没有 `data/stickers`，表情包相关的那项没素材可测。

**怎么办**：不用管，这是正常的。想看它跑起来，往 `data/stickers` 里放几张图再跑。

## 三、前端类坑

### 3.1 改了页面里的脚本，自检报语法错误

**现象**：`panel_check` 报某个 html 里的脚本解析失败，行号指向的地方看起来完全正常。

**为什么**：自检会把内联脚本抽出来单独检查，按普通脚本处理。页面里用了 `type="module"`，抽出来就变成了非法语法（顶层的 `import`、`export` 会直接炸）。

**怎么办**：

- 内联脚本统一用传统写法（IIFE 包一层），别上 module；
- 想验证，先手工抽出来跑一遍：

```powershell
node --check .\tmp-check.js
```

- 真要写模块化代码，放到单独的 `.js` 文件里，用 `<script src>` 引，别内联。

### 3.2 新接口一律 404

**现象**：代码写了，路由也 `include_router` 了，浏览器和 `curl` 都是 404。

**为什么**：面板挂在 `/` 上，框架按注册顺序匹配。静态挂载排到了前面，请求全被当成文件去找。

**怎么办**：把静态挂载放到最后。顺序只能是：内置路由 → 外置模块 → 面板静态目录。模块那条要用 `attach(app)`，不能用 `include_router`。

**验证**：故意访问一个不存在的路径，看返回的是框架的 404 还是静态目录的 404。两个不一样，能帮你判断请求走到了哪一层。

### 3.3 加了控件但点了没反应

**现象**：按钮在，样式也对，点下去什么都不发生，控制台也没报错。

**为什么**：三种可能——元素 `id` 和脚本里取的对不上；调用的接口后端没注册；脚本在元素渲染之前就执行了。

**怎么办**：

1. 跑 `scripts/panel_check.py`，它会逐条比对控件 id 和接口路径。
2. 控制台里 `document.getElementById('你的id')` 看一眼是不是 `null`。
3. 脚本放页面底部，或者等 DOM 就绪再绑事件。

### 3.4 改了样式刷新没变化

**现象**：改了 css，刷新还是老样子。

**为什么**：浏览器缓存了 css；或者你改的是令牌文件，但页面里压根没引它。

**怎么办**：强制刷新（`Ctrl+F5`）；确认页面 `<head>` 里引的是 `symvolve-tokens.css` 和 `symvolve.css`；改完再跑一次面板自检，确认没写裸色值。

## 四、打包类坑

### 4.1 装完起不来，安装包还小了三十兆

**现象**：安装包能装，双击没反应；一看体积，比正常的小了一大截。

**为什么**：打包时内核可执行文件没被复制进去。这一步不报错，只是安静地少拷一个文件。

**怎么办**：打包前先确认内核可执行文件真的在打包源里；打完对体积——Core 约 137 MB，Standard 约 223 MB，差出几十兆就是漏了。

### 4.2 启动动画不显示，功能都正常

**现象**：能启动、能用，就是没有开屏画面。

**为什么**：Electron 打包的资源白名单里漏了那个 html。漏了不报错，只是找不到。

**怎么办**：把开屏页加进打包白名单，重新打包，装一遍确认。

### 4.3 路径多套了一层，资源全找不到

**现象**：打包后程序说找不到内核，但文件明明在安装目录里。

**为什么**：Electron 打包后，资源根目录指向的是 `resources`。你在配置里又写了一个 `resources/...`，最后变成 `resources/resources/...`。

**怎么办**：配置里的相对路径从资源根开始写，别再带一遍 `resources`。装完之后实际点开目录看一眼层级，比对着配置猜快。

### 4.4 版本号不是合法 semver，打包直接失败

**现象**：`npm` 或者打包工具报版本号非法。

**为什么**：`0.2-P` 这种带字母后缀的写法不是 semver。打包工具内部要严格解析。

**怎么办**：两边分开写——打包配置里写 `0.2.0`，对外文件名和界面显示写 `0.2-P`。别为了好看去改打包工具的校验。

### 4.5 单文件安装包超过体积上限

**现象**：打大包时失败，或者打出来的 exe 装不上。

**为什么**：安装器格式对单文件有体积上限，大约 2 GB。塞了语音权重之后轻松超。

**怎么办**：发行版只打 Core 和 Standard（都在上限内）。带第三方权重的整合包不对外发，真需要就拆成「安装器 + 资源包」两段。

### 4.6 带中文的 PowerShell 脚本报「字符串缺少终止符」

**现象**：脚本在别人的机器上一跑就报错，报错位置在一个中文注释附近。

**为什么**：Windows PowerShell 5.1 按本地编码读 `.ps1`。文件存成无 BOM 的 UTF-8，中文就被读坏了。

**怎么办**：带中文的 `.ps1` 一律存成 **UTF-8 with BOM**。VS Code 右下角能直接改编码。

### 4.7 无控制台模式下 `print` 让程序崩掉

**现象**：打包后的程序一启动就退，日志里一行 traceback 指向某句 `print`。

**为什么**：无控制台模式下，标准输出和标准错误是空的。往空对象上写，直接抛异常。

**怎么办**：入口第一件事就是把它们兜住：

```python
import os
import sys

if sys.stdout is None:
    sys.stdout = open(os.devnull, "w")
if sys.stderr is None:
    sys.stderr = open(os.devnull, "w")
```

### 4.8 想让子进程活得比父进程久，结果脚本一行没跑

**现象**：父进程退出后子进程也没了；或者反过来，返回码 0 但脚本什么都没做。

**为什么**：进程创建标志选错了。某些组合下，子进程会被立刻回收，或者根本没进入解释器。

**怎么办**：要「父进程死了子进程还在」，用 `CREATE_NO_WINDOW | CREATE_NEW_PROCESS_GROUP`，别用 detached 那套。

## 五、发布类坑

### 5.1 发出去才发现仓库里有真实号

**现象**：翻提交记录，发现早前提交里有过真实 QQ 号、群号或者 key。

**为什么**：本地调试时顺手写进了代码或配置，提交前没扫。

**怎么办**：发布前必扫，命中就停：

```powershell
Select-String -Path (Get-ChildItem -Recurse -Include *.py,*.md,*.yaml,*.html) -Pattern "sk-|QQ号|群号|@qq\.com"
```

`config.local.yaml` 不参与（它不入库）。其余文件一律零命中。所有示例统一用 `123456789` / `sk-xxx`。

**已经进了历史**：改历史很贵。最稳的是重建一个干净的单提交仓库，推上去，然后核对提交数确实是 1。动手之前先 `git bundle create` 打一份备份——这一步省下来的时间，出事时要拿几倍还回去。

### 5.2 提交了不该提交的目录

**现象**：仓库里出现 `data/`、`*.db`、`node_modules/`、`.third_party/`。

**为什么**：`.gitignore` 漏了，或者用了 `git add -f`。

**怎么办**：先补 `.gitignore`，再从索引里移除（文件留在本地）：

```powershell
git rm -r --cached data
git commit -m "停止跟踪运行时数据"
```

本机数据一旦进了历史，就跟着历史走了。别指望「下次注意」。

### 5.3 中文文件名上传后变成乱码或者 `default.xxx`

**现象**：发布页上的附件名不是原来的名字。

**为什么**：托管平台对非 ASCII 文件名的处理不一致，会被截断或者转义。

**怎么办**：发布物一律用 ASCII 文件名，中文说明放进压缩包里面的文档。

### 5.4 删了 tag 重建，Release 变回草稿

**现象**：重新打了同名 tag，发布页却显示草稿，别人下载不到。

**为什么**：删 tag 会连带影响关联的 Release 状态。

**怎么办**：重建 tag 之后，手动把 Release 从草稿改成发布，再刷新页面确认匿名能下载。

### 5.5 提交作者邮箱被公开

**现象**：仓库的提交记录里带着私人邮箱。

**为什么**：本地 git 配置就是那个邮箱，提交时直接写进去了。

**怎么办**：发布前统一改成 noreply 邮箱；历史里已经有的，跟 5.1 一样走重建。

### 5.6 发布前没备份

**现象**：强推之后发现推错了，本地也没有可回退的完整副本。

**为什么**：直接 `push --force`，没留后路。

**怎么办**：强推之前先打包整个仓库：

```powershell
git bundle create ..\backup-$(Get-Date -Format yyyyMMdd-HHmm).bundle --all
```

出事了能从 bundle 里克隆回来。这一步只要十秒。
