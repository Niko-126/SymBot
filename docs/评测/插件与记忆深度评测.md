# 插件与记忆深度评测（2026-11-03）

> 这篇回答两个问题：**她的哪些能力是自己写的、哪些是别人的？记忆到底强在哪、弱在哪？**
> 想先看总榜，翻 [五机器人对比报告](五机器人对比报告.md)；想复跑，翻 [评测标准 v1.0](评测标准-v1.0.md)。

---

## 一、一句话结论

**她的「人」是百分之百自己写的，「嗓子」是百分之百别人的。**

人格、记忆、关系、作息、群聊调度、面板、工具环，都是核心自研。
语音合成、换声翻唱、以及 QQ 接入，全部依赖第三方件。

全量整合包那 9.4 GB 里，买的其实是那副嗓子。

---

## 二、三层边界

| 层 | 是什么 | 归谁 | 在不在仓库里 |
|---|---|---|---|
| **核心** | 人格 / 记忆 / 关系 / 生活 / 面板 / 工具 | 自研 | 在 |
| **插件** | 本地声音服务与换声模型 | 第三方 | 不在（随整合包附带） |
| **宿主** | QQ 接入端（OneBot v11） | 第三方 | 不在，用户自己装 |

清楚这条边界很重要：它决定了出问题时该找谁。

- 她说话不对味、记不住事、关系不往前走 → 找本项目。
- 她不能出声、唱歌跑调 → 先看声音服务，那是别人的。
- 她连 QQ 都收不到消息 → 先看 QQ 接入端，那是第三方框架。

---

## 三、体积占比：九成五买的是嗓子

| 指标 | 核心 | 第三方件 | 占比 |
|---|---|---|---|
| 文件数 | 2975 | 13724 | 第三方 **82.18%** |
| 字节 | 449 MB | 9544 MB | 第三方 **95.51%** |
| Python 有效行 | 48129 | 1296910 | 第三方 **96.4%**（含上游模型源码） |

外面流传两句话，一句对一半、一句不成立：

- 「体积 97% 是插件」——方向对，准确数字是 **95.51%**。
- 「代码 100% 是核心」——**不成立**。第三方侧的代码行数是核心的 27 倍，只是绝大部分是上游模型源码。

准确的说法还是开头那句：**人 100% 核心，嗓子 100% 插件。**

---

## 四、插件缺席时会发生什么

评测标准把「静默失败」列为重罪。这个项目同一份代码里有两种标准：

| 场景 | 表现 | 判定 |
|---|---|---|
| 语音合成失败 | **静默降级成纯文字**，无提示、无日志 | 重罪 |
| 记忆内核缺失 | 显式抛错，且注释写明「绝不静默返回空结果」 | 正确 |
| 翻唱失败 | 有回话，但原因统一说成「音太高」 | 失真 |
| 人声分离环境缺失 | 直接不可用 | 硬伤 |
| 一键启动 | 不拉声音服务 | 文档不符 |

这就是为什么「小白易用性」这一栏它拿不到满分：**四件事里有三件会静默或失真**。

> 0.2-P 已经改了其中两条：语音失败会明说原因，人声分离的路径改成配置项。剩下两条记在 [路线图](../../路线图.md) 里。

## 五、模块系统：系统在，生态是空的

模块运行时做得相当扎实：

- 清单六个必填字段校验、id 必须等于目录名；
- 入口文件三道关（不许跳出目录、必须在模块目录内、必须是 py 文件）；
- 能注册**工具 / 路由 / 钩子**三类；
- 注册到一半炸了会回滚，停用只是不加载，文件不动；
- 面板三个接口：列表 / 开关 / 重载。

但三个事实把它按在地上：

1. **全仓模块只有一个 hello**，它自己的清单写着「验收用」。
2. **注册的工具没有接进模型**：模型能用的工具是硬编码的三个，规划器也只认这三个。
3. 没有 MCP、没有权限模型、没有配额、没有市场。

**结论：插件系统是给未来留的口子，现在装不了真功能。** 这一维给 4 分，不是 7。

## 六、记忆评测

### 6.1 五分钟看懂（能力版）

```
你随口说一件事   → 她被记住
常提的           → 记得牢，越聊越清楚
很久不提的       → 慢慢变淡，提一句能捞回来
你钉住的         → 不参与淡忘，一直在
你问「还记得吗」 → 只要话里有它能对上的词，就能想起来
```

进到提示词里的，分三段：`【你记得的】`、`【之前聊过】`的摘要、`【之前没说完的】`。

### 6.2 和另外四家比

| 项 | **SymBot** | SMD-P | surfcore | qq-bridge | AstrBot |
|---|---|---|---|---|---|
| 按人分区 | 有 | 有 | 有（角色卡） | 弱（会话级） | 无 |
| 热度与衰减 | 有 | 有 | 无 | 无 | 无 |
| 冷归档可还原 | 有 | 有 | 无 | 无 | 无 |
| 可遗忘 | 有（留痕） | 有 | 弱 | 弱 | 无 |
| 可编辑正文 | **无** | 无 | 有（卡片） | 有（文件） | 无 |
| 语义/向量召回 | **无** | 无 | 弱 | 无 | 无 |
| 记忆相关测试 | 22 + 6 条 | 22 + 6 条 | 少量 | 无 | 无 |
| 整体分 | **9** | 9 | 7 | 5 | 3（未实现） |

一句话：**记忆这件事上，它是五家里唯一把「写、记、忘、归档、还原」做全的；也是五家里唯一一个「召回全靠字面匹配」的高分方案。**

前者是真本事，后者是真短板。

### 6.3 真正强的地方

- **结构完整度是满分**：记忆本体、线索、档案三层分开，热/冷双层，软合并还能还原。别家没有第二家做全。
- **按人分区做得干净**：同一个群里 A 说的话不会算到 B 头上，私聊和群聊分着算。
- **写入只有一个口子**：绕不过去，所以能导出、能搬、能审计。
- **纪律真的落到测试里**：视图拒绝写入、按人隔离、私聊群聊分流、一次召回只落一条审计——这几条边界全有断言钉着。

### 6.4 真正弱的地方

| # | 短板 | 后果 |
|---|---|---|
| 1 | **召回靠字面重合，没有向量** | 你换个说法，她就想不起来 |
| 2 | **没有语义去重** | 同一件事换个说法存两条 |
| 3 | **置信度不校准** | 显示 0.95 不代表 95% 会命中，它只是分数的换算 |
| 4 | **不能编辑正文** | 记错一个字，只能删了重记 |
| 5 | **没有多模态记忆** | 图片和语音的结果不进记忆本体 |
| 6 | **删除是软删** | 「忘记」= 从视图消失，底层数据还在 |
| 7 | **记忆在提示词里占比很小** | 见下一条 |

### 6.5 记忆在提示词里只占一点点

这是最该记住的一个数。某一轮真实对话的提示词构成：

| 段 | 占比 |
|---|---|
| 历史对话 | 34.6% |
| 语气样本 | 21.6% |
| 人格卡 | 14.1% |
| 状态与禁区等 | 19.5% |
| **记忆** | **1.8%** |
| 召回的往事 | 0 ~ 1.3% |

一套写了几千行的记忆系统，在这一轮里只占 56 个 token。

不是被截断——窗口用了不到 5%，是**设计上就只给了这么多**。

**结论：记忆在她的「人格构成」里是配菜，不是主菜。语气和人格才是主菜。**

这一点对用户的体感影响很大：她「像不像那个人」，八成靠语气和人格卡，两成靠记忆。

### 6.6 分轴打分

整体给 9 分，但拆开看更清楚：

| 轴 | 分 | 依据 |
|---|---|---|
| 结构完整度 | **10** | 三层分离、唯一写入口、按人分区、热冷双层、软合并可还原——别家没有第二家做全 |
| 召回质量 | **6** | 纯字面匹配，门槛偏低，没有向量和语义；但线索闸门的设计方向是对的 |
| 遗忘设计 | **7** | 线性衰减偏激进，靠重要度和钉住兜底算合理 |
| 可维护性 | **6** | 可解释、可审计、有 28 条断言；但有死代码、无编辑接口 |
| 提示词占比 | **4** | 只占 1.8%，是配菜不是主菜 |

**综合 9 分打的是「结构完整度与工程纪律」，不是「召回准确率」。**
如果只用召回准确率当尺，同源代码只能给 6–7 分——这句话必须写清楚，否则 9 分会被误读成「语义记忆」。

## 七、结论

1. **归属很清楚**：人格、记忆、关系、生活、面板是自研；语音、换声、翻唱是第三方的；QQ 接入是第三方框架的。全量版 95.51% 的体积买的是嗓子。
2. **插件系统存在但没有生态**：运行时和面板接口都到位了，可注册的工具没接进模型，模块只有 hello 一个示例。这一维 4 分，不能再高。
3. **记忆是全场最强，但强在结构不在算法**：三层分离、唯一写入口、按人分区、软合并可还原、28 条断言——这些是真护城河；无向量、无语义去重、置信度不校准、不能编辑正文、只占提示词 1.8%——这些是真短板。
4. **最该先修的三件事**：
   - 语音失败从静默改成显式提示（已修）；
   - 补一个「编辑记忆正文」的入口；
   - 把注册的工具真正接进模型的工具表。

---

## 八、这份评测的局限

- 作者自己做的，不是第三方认证。
- 只看「能力有无」和「工程纪律」，没有做大规模召回准确率的量化测试。
- 分数是 2026-11-03 的快照。
