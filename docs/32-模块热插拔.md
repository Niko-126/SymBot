# 32 · 模块热插拔（modules/）

> 覆盖：`app/core/modules.py`（发现 / 校验 / 加载 / 注册表）、`app/api/modules_api.py`（面板接口）、
> `modules/README.md`（用户说明书）、`modules/hello/`（示例模块）。
> 一句话：**用户从 GitHub 下个模块解压到 `modules/<id>/` 就生效，不用改一行代码。**

---

## 1. 目标与边界

| 要 | 不要 |
|---|---|
| 零改码：只认 `modules/*/manifest.json` | 不自动 `pip install`（`requires` 只校验，缺包就报缺哪个） |
| 放错不崩：坏模块只标 `failed`，内核照常起 | 不做沙箱：模块代码就在内核进程里 |
| 热生效：`reload` 换工具 / 路由 / 钩子，不重启 | 不自动联网、不自动更新、不校验签名 |
| 开关持久：`kv` 里记 `module_enabled:<id>` | 停用不删文件（删目录才是卸载） |

**为什么不做沙箱**：Python 层做不出真隔离（`ctypes`、`sys.modules` 都绕得过去），
假沙箱只会让用户误以为安全。所以策略是**把边界写清楚 + 只装信得过的**（见 §4、§9）。

## 2. 目录结构

```
modules/
├── README.md              ← 内核第一次启动自动生成（也可 python -m app.core.modules --init）
├── hello/                 ← 示例模块：一个工具 + 一个路由
│   ├── manifest.json
│   └── hello.py
└── <id>/                  ← 第三方模块：目录名必须 == manifest.id
    ├── manifest.json
    ├── main.py            ← entry 指向它
    └── …（模板 / 数据 / 子脚本都放这一层）

app/core/modules.py        ← 本功能全部逻辑（发现 / 校验 / 加载 / 注册表 / 路由挂载）
app/api/modules_api.py     ← /v1/console/modules* 三个接口
```

`MODULES_DIR = RESOURCE_ROOT / "modules"`（`app/core/paths.py`）。开发态 = 仓库根下的 `modules/`，
打包态 = PyInstaller 解包目录。**不跟着 `SYMEM_DATA` 走**：模块是代码不是数据，
换数据根不该让模块消失。

## 3. manifest.json 与校验

```json
{
  "id": "hello",
  "name": "示例模块 · 你好",
  "version": "1.0.0",
  "entry": "hello.py",
  "kind": "mixed",
  "requires": []
}
```

| 字段 | 校验 | 不合格的报错（面板原文） |
|---|---|---|
| `id` | 必填；`^[a-z0-9]+(?:-[a-z0-9]+)*$`；**等于目录名** | ``id 不合法：`Hello`（只能小写字母、数字和连字符，例：hello-world）`` |
| `name` | 必填非空字符串 | `name 必须是非空字符串` |
| `version` | 必填非空字符串 | `version 必须是非空字符串（例：1.0.0）` |
| `entry` | 必填；相对路径；不许 `..`；解析后仍在模块目录内；`.py`；文件存在 | ``entry 不许往上跳：`../../evil.py`（只能指向模块目录里的文件）`` |
| `kind` | ∈ `tool` / `route` / `hook` / `mixed` | `kind 只能是 tool / route / hook / mixed，现在是 `x`` |
| `requires` | 字符串列表；包名合法；**逐个查装没装** | `缺依赖：requests（pip install requests；内核不自动装）` |

补充规则：

- `manifest.json` 用 `utf-8-sig` 读，**记事本存的 BOM 也认**。
- `entry` 里的 `\` 会先归一成 `/`（Windows 用户手写反斜杠不至于报错）。
- 目录里**没有** `manifest.json` 的文件夹直接忽略（`__pycache__`、半成品空目录不刷屏）；
  以 `.` / `_` 开头的目录也跳过。
- 多个字段同时错时，`error` 用「；」拼前 4 条，剩下的显示 `…`（面板一行放得下）。
- 额外字段（`author`、`description`、`homepage`…）随便写，不校验也不报错。
- `kind` 只作**声明**（面板分类 / 用户预期用），不做强制拦截：`tool` 模块顺手挂个路由也照样能用。
- 依赖判断走两条路：`importlib.metadata.distribution(名)` 查发行名，再 `find_spec(名)`
  查 import 名——所以 `PyYAML`（发行名）和 `yaml`（import 名）两种写法都认。

## 4. 安全边界

**模块代码拥有内核的全部权限**：读任意文件、发网络请求、直接写 `life.db`、改 `sys.modules`。

因此：

- 面板上「模块」页必须写「只装信得过的」，`modules/README.md` 也写明；
- `requires` 只校验，绝不替用户 `pip install`（装包 = 执行任意 setup 代码）；
- 模块不能改内核：只能通过 `register(api)` 挂工具 / 路由 / 钩子；
- 出问题时**停用**（立刻下架）+ **删目录**（彻底清除），内核不需要重启。

## 5. 生命周期

```
内核启动 create_app()
   └─ modules.attach(app)                 ← main.py 两行接线（见 §11）
        ├─ ensure_ready()                 建 modules/ + README.md（缺才写）
        ├─ discover()                     扫目录 / 读 manifest / 校验 → list[ModuleInfo]
        ├─ 逐个：enabled? → import entry → register(api)
        │        └─ 任何一步炸：只标记该模块 failed + error，不抛给调用方
        ├─ registry() 单例装好工具 / 路由 / 钩子
        └─ mount(app)                     把模块路由插到面板静态 Mount 之前
面板点「重新加载」→ POST /v1/console/modules/reload
        └─ reload(app) = load_all() + mount(app)     ← 工具/路由/钩子当场换新
面板点开关 → POST .../toggle → 写 kv → reload(app)
```

几个关键实现点（改代码前先看这几条）：

1. **import 用 `spec_from_file_location("symbot_modules.<id>", entry)`**，并传
   `submodule_search_locations=[模块目录]`，因此：
   - 模块内部可以 `from .helper import x`（相对导入）；
   - reload 时把 `symbot_modules.<id>` 连同 `symbot_modules.<id>.*` 从 `sys.modules`
     里摘掉，**改完代码 reload 就生效**，不会拿到旧模块对象。
2. **路由必须插在面板 `Mount("/")` 之前**：`main.py` 最后会
   `app.mount("/", StaticFiles(...))`，Starlette 按顺序匹配，挂在这个 Mount 后面的路由
   永远收不到请求。`Registry.mount()` 每次先摘上一轮挂的路由，再插到第一个 `Mount` 之前。
3. **注册到一半炸了的模块要回滚**：注册了 `tool_a` 之后 `register()` 抛异常，
   `tool_a` 会被摘掉（`_unregister`），不留半截。
4. **`reload` 不清 `_mounted`**：清掉就摘不掉旧路由，停用后旧 handler 会一直活着。
5. `register(api)` 只调一次；模块顶层代码在 import 时执行——**别在顶层做慢操作、别起线程**，
   要后台任务请自己起线程/协程并在文档里写清楚。

## 6. 注册表（`registry()`）

全局单例，模块和内核都从这里取东西：

| 成员 | 用途 |
|---|---|
| `registry().tools` | `{名字: ToolEntry(name, fn, desc, module_id)}` |
| `registry().call_tool(name, args=None)` | 跑工具；**永不抛**，失败 `{"ok": False, "reason": …}` |
| `registry().hooks` | `{事件: [(module_id, fn), …]}` |
| `registry().emit(event, payload)` | 触发钩子；单个钩子异常只进返回值 |
| `registry().modules` | `{id: ModuleInfo}` |
| `registry().mount(app)` | 挂/摘路由（幂等） |
| `registry().generation` / `loaded_at` | 加载代数 / 时间，面板可判断是否已加载 |

模块拿到的 `api` 只有三个方法（另有 `api.dir`、`api.log`）：

```python
def register(api):
    api.register_tool("hello_ping", hello_ping, desc="示例工具")   # fn(**args) -> dict
    api.register_router(router)                                    # fastapi.APIRouter
    api.register_hook("message.after", on_message)                 # fn(payload: dict)
```

钩子事件名**不预设**：内核（或另一个模块）在合适的位置
`registry().emit("message.after", {"text": …})` 即可，模块只管挂。

## 7. 冲突与优先级

**加载顺序 = 模块目录名字典序**（`sorted()`），所以行为可复现。

| 冲突类型 | 规则 | 表现 |
|---|---|---|
| 同名工具 | **先到先得** | 后注册的模块加载失败，`error` = ``工具 `dup_tool` 已被模块 `aaa` 注册（先到先得），本模块加载中止`` |
| 同名路由 | 都挂上，Starlette 按挂载顺序匹配 | 字典序靠前的模块赢，后挂的不可达；**约定模块路由自带前缀** `/v1/modules/<id>/…` |
| 同名钩子 | 不冲突，全部执行 | 单个钩子异常只记在 `emit()` 返回值里 |
| 与内置工具同名 | 不冲突 | 内置在 `app/tools/registry.py` 的 `SPECS`，模块工具在 `registry().tools`，两个命名空间 |
| 停用一方后 | 名额空出来 | 之前因重名失败的模块，下次 `reload` 会自动接管 |

## 8. 启用 / 停用（kv）

- 键：`module_enabled:<id>`，值 `"1"` / `"0"`。
- **空值 = 默认启用**：装进来就能用，不需要先去面板点开。
- 停用只是不 import、不挂工具路由，**文件一个不动**；再启用立刻回来。
- `toggle` 会立刻 `reload`，所以停用后工具/路由当场下架（不用重启内核）。
- 想彻底忘掉某个模块的开关（重装回到默认启用）：

```sql
DELETE FROM kv WHERE key = 'module_enabled:<id>';
```

## 9. 卸载

1. 面板「模块」→ 关掉开关（可选，但能让工具立刻下架）；
2. 删掉 `modules/<id>/` 整个目录；
3. 面板点「重新加载」（或重启内核）。

残留的 `kv` 键不影响运行；同 id 再装回来时会沿用上次的开关状态，
想恢复默认就按 §8 删键。**不要**去动 `app/` 里的代码——卸载模块永远不需要改代码。

## 10. 失败排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 面板里根本看不到模块 | 压缩包多套了一层（`modules/x/hello/manifest.json`） | 把内层目录提出来，让 `modules/<id>/manifest.json` 直接存在 |
| `id 与目录名不一致` | 文件夹叫 `Hello-1`，manifest 里写 `hello` | 改名，两边一致；id 只许小写字母/数字/连字符 |
| `缺依赖：xxx` | `requires` 里声明的包没装 | 自己 `pip install xxx`；内核不替你装 |
| `entry 文件不存在` | entry 写错路径 / 只传了 manifest 没传代码 | 对照目录里的实际文件名 |
| `entry 不许往上跳` | entry 用了 `../` | entry 只能是模块目录里的相对路径 |
| `语法错误 xxx.py:12` | 模块代码本身写错 | 按行号改；或先停用再排查 |
| `entry 里没有 def register(api)` | 入口文件忘了写 register | 补上（见 §6） |
| `工具 already registered` | 和另一个模块撞名 | 改名，或停用先占位的模块后 reload |
| 路由 404 | 模块没注册 router / `kind` 不是 route/mixed / 已停用 | 看面板 `routes` 列表；确认路径前缀 |
| 启动变慢 | 模块顶层做了重活（读大文件、联网） | 挪进工具函数里，别放 import 期 |
| 停用后工具还能用 | 只改了 kv 没 reload | 走面板开关（会自动 reload），或 `POST /v1/console/modules/reload` |

调试入口：`GET /v1/console/modules` 里每个模块都带 `error`（人话）、`warnings`、
`loaded`、`tools`、`routes`、`hooks`；`registry().generation` 能看出加载过几次。

## 11. 面板接口与 main.py 接线

三个接口（prefix `/v1/console`，鉴权与 `console.py` 同口径：`console.token` 配了就要
`X-Console-Token` 或 `?token=`；**没有 import `console._console_auth`，怕绕成环，本地抄了一份**）：

```
GET  /v1/console/modules
  → {items:[{id,name,version,kind,enabled,source,error,warnings,loaded,loaded_at,
             tools:[{name,desc}],routes:[{path,methods}],hooks:{event:n}}],
     total, dir, notes, generation, loaded_at, tools:[…]}
POST /v1/console/modules/{module_id}/toggle   body {"enabled": true|false}
  → {ok, id, enabled, module:{…}}            不存在 → 404
POST /v1/console/modules/reload
  → {ok, total, loaded:[…], failed:[{id,error}], disabled:[…], dir, notes, items:[…], mounted}
```

`main.py` 只需要两行（放在其他 `include_router` 之后、面板 `app.mount("/", …)` 之前）：

```python
    from app.core import modules as modules_mod
    modules_mod.attach(app)
```

**为什么是 `attach(app)` 而不是 `include_router`**：模块路由是运行时才知道的，
必须由 `attach` 在面板 Mount 之前插进去；它同时负责启动时加载模块（工具在第一次聊天前就位）。
`modules_api` 里还留了兜底：如果 `main.py` 只 include 了接口没 attach，
第一次打开「模块」页会触发一次 `ensure_loaded()`。

CLI 自检：

```powershell
python -m app.core.modules --init   # 建 modules/ + README.md
python -m app.core.modules --list   # 打印模块清单（JSON）
```
