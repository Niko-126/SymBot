# 33 · 水印与指纹

> 这一层给的是**廉价证据**，不是版权登记，也不是防抄。这篇把"挡得住什么、挡不住什么"写清楚，
> 免得日后自己高估它。

---

## 1. 解决什么问题

代码会被 fork、被搬进别的项目、被模型整段读过再吐出来。可见的版权头会被删，注释里的作者名会被
lint 和重构工具顺手清掉。要留的是这样一枚标记：

- 人读代码时**看不见**，不影响阅读；
- 机器跑代码时**不参与逻辑**，不影响行为、不破语法；
- 搬走时会**跟着走**，而且能指回"哪个文件、哪一段"。

分三层，代价从低到高：

| 层 | 落在哪 | 数量 | 默认 | 删掉的代价 |
|---|---|---|---|---|
| 文本水印 | 每个 `.py/.md/.html/.css` 的 docstring 内 / 注释行尾 | 130 个文件 | 开 | 无明显代价，但删了就是"少了 34 个看不见的字符" |
| 派生常量锚 | 12 个核心 `.py` 的一个字面量 | 12 处 | **关**（`--anchors`） | 删常量 → `NameError`；改值 → 行为变 |
| 结构指纹 | `app/core/watermark.py` 的 `META_FIELD` | 1 | 常量在位，接入由 Lead 做 | meta 少一个字段 |

## 2. 为什么是零宽字符

对比四种常见做法：

| 做法 | 能不能被"顺手"删掉 | 影响阅读 | 能定位到文件 | 能证明来源 |
|---|---|---|---|---|
| 可见版权头 `# (c) ...` | 一秒删 | 影响 | 不能 | 弱，谁都能写 |
| 注释里的作者名 | 重构/lint 会清 | 轻微 | 不能 | 弱 |
| 源码整文件哈希入库 | 改一个字就失效 | 无 | 不能（只能整仓比） | 中，但改一行就断 |
| **零宽字符水印** | 需要专门找 | **无** | **能** | 中，跟密钥绑定 |

用的四个字符都是 Unicode `Cf`（格式符）类：

| 字符 | 名字 | base-4 值 |
|---|---|---|
| `U+200B` | ZERO WIDTH SPACE | 0 |
| `U+200C` | ZERO WIDTH NON-JOINER | 1 |
| `U+200D` | ZERO WIDTH JOINER | 2 |
| `U+FEFF` | ZERO WIDTH NO-BREAK SPACE（BOM 同一个码位） | 3 |

它们在编辑器里不占宽度、不触发高亮、不参与换行；`git diff` 里它就在那儿但看不出来。
复制粘贴、打包、整段搬运都会带着走；反过来，`cat -A`、十六进制查看、编辑器"显示不可见字符"
一开就能看见——这一点不打算藏。

**为什么只往 docstring 和注释里塞**：从 CPython 3.14 起，字符串与注释之外的零宽字符会直接
`SyntaxError: invalid non-printable character`（本机 3.14.8 实测）。所以注入点只有两个：
模块 docstring 收尾引号之前、`#` 注释的行尾。shebang 行和编码声明行会跳过——水印挂在 shebang
行尾会让 Unix 找不到解释器。

## 3. 指纹怎么算

```
fp   = HMAC-SHA256(key, b"symbot" + relpath)[:8]      # 8 字节 = 64 bit
符号 = base-4 展开成 32 位，0/1/2/3 → 四个零宽字符
串   = U+FEFF + 32 个符号 + U+FEFF                    # 共 34 个字符
```

几个刻意的选择：

- **绑相对路径**：同一个文件换个位置、改个名字，指纹就对不上。这是取舍（见 §4），换来的是
  "命中"能指到具体文件，而不是只有"这堆代码像是他的"。
- **8 字节 / 32 个符号**：2 bit × 32 = 64 bit，130 个文件撞不上；再长会让每处多出肉眼可见的
  字节数，没必要。
- **定界符和 `3` 共用 `U+FEFF`**：载荷里本来就可能出现定界符，所以解析不用朴素正则，改成
  "找定界符 → 取 32 位定长窗口 → 两头都是定界符才算"（`_envelope_spans`）。代价是多扫几遍，
  一个文件几毫秒。
- **幂等**：`embed()` 先 `strip()` 再写。重复跑不叠加，`strip()` 之后跟注入前逐字节一致。
- **不加密、不带版本号/时间戳**：水印只承担"是不是我写的"，多写的每个 bit 都是多一条线索。

## 4. "AI 认不出"的边界

**挡得住的**

- 人肉读代码：看不见。
- 整段复制、翻译、打包分发、二次 fork：零宽字符通常原样保留，指纹跟着走。
- 模型"读过一遍再引用"：只要逐字保留，就跑不掉。

**挡不住的**

- **知道有这回事的人**：开"显示不可见字符"、`cat -A`、或者直接读这个仓库的 `docs/33`。
  这套东西的隐蔽性来自"没人想到去看"，不是来自"看不见"。
- **清理不可见字符的工具**：一次正则批量洗，成本接近零。
- **整文件重写**：模型看完再重写，通常不会逐字复制，水印就丢了。
- **改名/移动文件**：路径绑定的指纹失效（结构指纹不受影响）。
- **格式化工具**：`black` / `prettier` 一般不动 docstring 内的字符，但会改写注释位置，
  注释行尾的水印有概率被挪走或合并。

所以定位是：**低成本、低打扰、能当"来源之一"的证据**。它防的是"顺手 copy 一下"，防不了
"知道有这层、专门洗一遍"。

## 5. 派生常量锚：删了会变行为

形态（以 `app/core/continuity.py` 为例）：

```python
# 注入前
str(detail or "")[:500],

# 注入后
# 连续性摘要的截断宽度（面板按这个宽度出列表）
_WM_TRACE_TRIM = 500

str(detail or "")[:_WM_TRACE_TRIM],
```

- **为什么"删了会变行为"**：值被换成了模块级名字。删掉常量 → 调用处 `NameError`；
  把 `500` 改成 `300` → 截断长度真的变了。这不是"藏"，是长在代码结构里。
- **为什么"注入前后行为一致"**：值与原字面量**完全相等**（`500 = 500`），属于等值替换。
  自测里注入后跑 `py_compile`，并跟原件逐字节 diff 过。
- **只在 `--anchors` 下做**：清单在 `scripts/apply_watermark.py::ANCHOR_SITES`，12 个文件。
  每条都要求原字面量在文件里**唯一命中**，不唯一或找不到就报"冲突/跳过"并且不动那一行。
- **`derived_const(relpath, modulo)`**：路径派生的整数（不含密钥，换机也一样），留给"想用
  派生值"的场合。默认**不用它锚数值**——锚数值必然改行为；它的实际用途是派生 §6 的字段名。

## 6. 结构指纹

`app/core/watermark.py` 里有两个常量：

```python
META_FIELD = struct_field("app/core/watermark.py")   # 例如 "frame_ms"
META_VALUE = derived_const("app/core/watermark.py", 9973)  # 例如 9781
```

用途：日志和响应 meta 里出现 `{"frame_ms": 9781}` 这种"毫无异常"的字段。正常代码里没人会在意
一个叫 `frame_ms` 的整数；但它稳定、可复现、不需要密钥，两份实现里同时出现同一个字段名和
同一个值，就是一条结构侧的线索。

`watermark.meta()` 直接返回 `{字段名: 值}`，接入点（日志 / 响应 meta）由 Lead 在冻结后统一接。

## 7. 使用流程

```powershell
# 1）一次：生成密钥（32 字节随机，写到 scripts/.wm.key，已被 gitignore）
.\.venv\Scripts\python.exe scripts\apply_watermark.py --init

# 2）先看会改哪些文件（不落盘）
.\.venv\Scripts\python.exe scripts\apply_watermark.py --write --dry-run

# 3）注（默认 app/；也可以 --paths app/core app/web）
.\.venv\Scripts\python.exe scripts\apply_watermark.py --write

# 4）校验：命中数 + 缺失清单（不打印指纹本体）
.\.venv\Scripts\python.exe scripts\verify_watermark.py --scan app

# 5）单文件说明：这个文件有哪几种水印
.\.venv\Scripts\python.exe scripts\verify_watermark.py --explain app/core/continuity.py
```

时机：

- **文本水印在代码冻结之后做**。注入会让每个文件 +34 个字符，`git diff` 里表现为"文件改了但
  看不出改了啥"，冻结前做会干扰别人的评审。
- **锚点在更后面**。它会动真实逻辑行，必须先 `py_compile` + 冒烟，再让 owner 点头。
- **回滚**：`--strip` 逐字节回到注入前（自测验证过），`--strip --anchors` 连常量锚一起回滚。

退出码：`apply` 0 成功 / 1 有文件失败 / 2 无可用密钥或参数不对；
`verify --scan` 0 全命中 / 1 有缺失 / 2 无可用密钥。

## 8. 换机与密钥托管

优先级：`SYMEM_WM_KEY` 环境变量 → `scripts/.wm.key` → 内置派生盐。

| 场景 | 做法 |
|---|---|
| 本机开发 | `--init` 一次，密钥留在 `scripts/.wm.key` |
| CI / 打包机 | 把 64 位 hex 塞进 `SYMEM_WM_KEY`（secret），不落文件 |
| 密钥放别处 | `SYMEM_WM_KEY_FILE` 指向路径 |
| 换机 | 安全拷贝 `.wm.key`；**别走 git，别贴群** |
| 备份 | 密码库/离线介质，跟仓库分开放 |

要点：

- **丢密钥 = 老文件的水印再也没法认证**。只能重新 `--init` 再重注一遍（旧串会被 `strip` 掉再写
  新串，不会叠加），但**已经发出去的旧版本认不回来了**。
- 派生盐模式（没密钥）：`--write` 拒绝签发并退出 2，`--scan` 也退出 2。它只是"没带证的人"。
- 轮换密钥：换完对全量重跑一次 `--write`，再跑 `--scan` 确认全命中。

## 9. 被侵权时怎么取证

1. **先冻证据**：对方仓库的 `git bundle` 或整目录压缩 + 时间戳，别只截图。
2. **别急着 `--scan` 原件**：先确认副本没被改过（`git status` / 校验和）。
3. **跑覆盖**：`--scan <对方副本>` 只看两个数——命中文件数、命中比例。这一步不输出指纹本体。
4. **结构侧优先**：12 个锚点常量名与位置、`META_FIELD`、文档措辞、注释逐字重合——
   这些"看着像个正常项目"的东西同时撞车的概率，比一段代码相似更说明问题。
5. **指纹侧作辅助**：零宽串可能被洗掉、被挪走，命中是加分项，不是唯一依据。
6. **口径**：技术上能说"高度一致、含本项目水印"，法律上是不是侵权由律师按当地法判断。
   文档只把技术事实摆齐，不替人下结论。

## 10. 已知弱点（写出来免得自欺）

- 一次性清理不可见字符就能洗掉文本水印，成本极低。
- 绑相对路径：改名、挪目录即失效。
- 载荷只有 64 bit，没有版本号和时间戳（故意不加）。
- 抗不了"读懂再重写"。
- 锚点清单就在仓库里，对手照着删一样能删干净。它提高的是"顺手抄干净"的成本，并留下痕迹，
  不是物理上删不掉。

这套东西的价值排序：**结构指纹 > 常量锚 > 文本水印**。前两个不好"顺手"处理，最后一个好处理，
但它铺得最广、最容易命中。

## 11. 自测（`.tmp/wm-drill/`，跑完整个目录删掉）

```powershell
$env:SYMEM_WM_KEY = (Get-Content .tmp\wm-drill\.wm.key -Raw).Trim()
.\.venv\Scripts\python.exe scripts\apply_watermark.py --write --paths .tmp\wm-drill\src
.\.venv\Scripts\python.exe scripts\verify_watermark.py --scan .tmp\wm-drill\src
```

检查点：

- 注 5 个 `.py` → `--scan` 命中 5、缺失 0、退出码 0；
- 抹掉其中 1 个的水印 → `--scan` 报"缺失 1"并列出文件名、退出码 1；
- 再跑一次 `--write` → `注入 0 / 已是 5`，文件 SHA256 不变（幂等）；
- `--strip` → 5 个文件与原件的 SHA256 全部一致（含 CRLF 文件）；
- 注入后 `python -m py_compile` 全部通过；
- 锚点：`--write --anchors --root <临时根> --paths app/core/continuity.py` 后 `py_compile` 通过，
  `--strip` 回滚后与原件逐字节一致。
