> 上游：[22-testing.md](22-testing.md)（怎么跑、期望多少）｜下游：[21-scripts.md](21-scripts.md)（编排脚本）

## 1. 这一层干什么

`app/qa/` 是一套**独立的、不改 `app/` 既有行为的测试底座**。它把仓库里每一个可执行面（模块、类、函数、方法、HTTP 路由、CLI 子命令、数据库表、配置键、人格键、会话场景）都变成一条有 ID 的 `Item`，先登记、再逐条执行、再把异常折成带严重级的 `Finding`，最后出一份结论先行的报告。

它解决的是"只跑了 smoke 就以为全绿"这类问题：

- **不抽样**：`inventory` 用 AST 扫全仓，列出来的条目不允许静默丢掉（`NOTRUN` 必须为 0）。
- **三层执行**：静态反射（L0）→ 进程内真调（L1）→ 子进程隔离跑（L2）→ HTTP 全量打（L4）→ 双 AI 会话（L3）。
- **四重隔离**：临时数据根、mock provider、断网守卫、密钥遮罩——由 `sandbox.py` 统一在 `import app.*` 之前完成。
- **只读 `app/`**：底座自己不改被测代码；发现问题只记 `Finding`，不修。

## 2. 全局硬规则（`CONTRACT.md` §0）

| # | 规则 | 为什么 |
|---|---|---|
| 1 | `sandbox.prepare_env()` **必须最先执行**（在 import 任何 `app.core.*` / `app.mind.*` 之前） | `app.qa.*` 模块禁止在模块级 import `app.core/app.mind/app.memory`，一律函数内惰性 import；否则 `import app.main` 的建库副作用会先发生，临时数据根白设 |
| 2 | 只写自己负责的文件，不碰别人的，不改 `app/`，不 `git commit` | 底座是观察者 |
| 3 | 每个 phase **先把 Item 全量注册（`NOTRUN`）**，再执行、再 `mark` | 保证"列了没跑"可见 |
| 4 | 任何写进报告的字符串都要过 `sandbox.mask()` | 转录里不许出现 api_key / app_token / 真实 QQ 号 |
| 5 | 需要外部依赖（真网络、NapCat、官方 WS、无 key）的项：`mark(SKIP, reason)` | 不许静默丢掉 |
| 6 | 单个调用必须带超时（默认 20s）+ 异常包裹 | 不许让一个坏函数拖死整轮 |
| 7 | 输出只用 `types.Item / Finding / TurnRecord / PhaseResult` | 各写一套 dict 会让报告静默丢数据 |

## 3. 数据契约（`app/qa/types.py`，116 行）

四张 dataclass，`asdict()` 直接序列化：

### 3.1 `Item`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | str | 唯一：`FN:app.memory.h2:add` / `ROUTE:POST /v1/chat` / `CLI:serve` / `TBL:mem_item` / `CFG:provider.model` / `PERSONA:speech` |
| `kind` | str | `fn` / `method` / `route` / `cli` / `table` / `config` / `persona` / `scenario` / `module` / `class` |
| `name` | str | 展示名 |
| `module` | str | 所属模块（`app.memory.h2` / `app.api.routes` / `-`） |
| `line` | int | 源码行号 |
| `risk` | str | `read` / `write` / `net` / `llm` / `hang` / `danger` |
| `plan` | str | `L0` 静态 / `L1` 进程内 / `L2` 子进程 / `L3` 会话 / `L4` 路由 |
| `status` | str | `OK` / `RAISED` / `SKIP` / `HANG` / `NOTRUN` / `EXPECTED` |
| `detail` | str | 结果摘要 |
| `extra` | dict | 附加信息（如 `{"private": True}`） |
| `ts` | float | 登记时间戳 |

状态语义：

| 状态 | 含义 |
|---|---|
| `OK` | 跑通且符合预期 |
| `RAISED` | 调用/请求抛异常（附 traceback 首帧） |
| `SKIP` | 按规则跳过，**必须带 reason** |
| `HANG` | 超时 |
| `NOTRUN` | 列了但没轮到（截断/中止）——**这是失职信号** |
| `EXPECTED` | 该抛且抛了（负向用例通过） |

### 3.2 `Finding`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | str | 规则 ID，如 `R12_group_explicit` |
| `severity` | str | `P0` / `P1` / `P2` / `INFO` |
| `area` | str | 模块/功能域 |
| `title` | str | 一句话结论 |
| `detail` | str | 证据描述 |
| `evidence` | dict | 原始数据（截断后的回复、状态快照） |
| `repro` | str | 复现步骤 |
| `item_id` | str | 关联的 Item |

严重级定义（`SEVERITY_ORDER = {P0:0, P1:1, P2:2, INFO:3}`）：

| 级 | 含义 |
|---|---|
| `P0` | 数据损坏 / 安全 / 崩溃 / 静默失败 —— 任何一条即判红（退出码 1） |
| `P1` | 功能错误 / 契约不符 / 明显出戏 |
| `P2` | 体验 / 健壮性 / 口径不一致 |
| `INFO` | 只记录 |

### 3.3 `TurnRecord`

`scenario` / `index` / `role`（`user`/`her`）/ `text` / `latency_ms` / `meta` / `findings[]`。

### 3.4 `PhaseResult`

`phase` / `started` / `ended` / `items[]` / `findings[]` / `notes`，另有：

- `finish()` → 打结束时间戳并返回自身
- `secs` 属性 → 耗时（秒，两位小数）
- `counts()` → 按状态计数
- `to_dict()` → 报告用

## 4. 六个 phase

### 4.1 `inventory.py`（1122 行）—— 先列全清单

```python
def build() -> list[types.Item]        # 全量清单
def manifest() -> dict                 # {"counts": {...}, "by_module": {...}, "generated_at": ...}
def probe_targets() -> list[dict]      # [{"module","qualname","is_async","sig","risk","line"}]
```

- 用 `ast` 扫 `app/**/*.py`，**不 import**（import 有副作用）；再对 `app/api/*.py` 补路由（方法 + 路径）。
- `risk` 判定靠 token 集合：

| risk | 触发 token（节选） |
|---|---|
| `write` | `INSERT` / `UPDATE` / `DELETE` / `h2.add` / `store.add` / `forget` / `terminate` / `compact` / `restore` / `ingest` / `push` / `send` |
| `net` | `httpx` / `requests` / `socket` / `bili` / `harvest` / `fetch` / `urlopen` |
| `llm` | `rt.llm` / `judge` / `models.pick` |
| `hang` | `while True` / `sleep(` |
| `danger` | `subprocess` / `rmtree` / `unlink` / `uninstall` / `release` / `pyinstaller` |

- 私有函数（`_x`）也列，`kind="fn"` + `extra={"private": True}`，默认 `plan="L0"`。

**实测规模（2026-11-01 02:26 跑 `--phase inventory`）**：

| 维度 | 分布 |
|---|---|
| 总数 | **1,893 条 Item** |
| kind | fn 1289 / method 151 / route 126 / module 108 / class 91 / config 59 / table 37 / persona 22 / cli 10 |
| risk | read 1260 / write 542 / llm 38 / net 32 / hang 11 / danger 10 |
| plan | L0 992 / L1 753 / L4 126 / L2 22 |

route 126 的构成：`routes` 59 + `console` 42 + `trend` 12 + `group` 10 + `onebot` 1 + **`main` 2**（`/` 与 `/index.html` 的占位页兜底）。**业务 API 操作是 124 条**（详见 [12-api.md](12-api.md)）。

### 4.2 `static_probe.py`（220 行）—— 静态项真验一遍

| 条目类型 | 怎么验 |
|---|---|
| `module` | 真的 `importlib.import_module` |
| `class` | 真的 `getattr` 拿到 |
| `config` | 用 `cfg` 单例真解析出值（`CFG:provider.model` 这类） |
| `table` | 真查 `sqlite_master`（实测 37 张业务表全过） |
| `persona` | 人设 YAML 真读出 22 个顶层键 |

### 4.3 `routes_fuzz.py`（1129 行）—— 全量 HTTP 对抗

```python
def register(reg: Registry) -> None                 # 注册所有 route item（含 payload 变体数）
async def run(reg: Registry) -> types.PhaseResult   # 用 httpx ASGITransport / TestClient 打全部路由
```

- 必须覆盖 `app.openapi()` 里的**全部** `(method, path)`，不接受抽样；**注册数 ≠ OpenAPI 数直接抛错**。
- 每个路由至少：1 个正常 payload + 1 个对抗 payload（空串 / 超长 8k / `{{}}` / `'\0'` / SQL 注入串 / 未授权）。
- 判定：任何 5xx → P0；返回非 JSON（除静态页）→ P1；鉴权接口无 token 却 200 → P1（已知现状，标 `expected`）。
- 路径带 `{param}` 的：先填合理值，再填 `__adv__` 垃圾值。

### 4.4 `probe.py`（1539 行）—— 每个可调用对象真调一次

三层执行计划：

| 层 | 做法 | 约束 |
|---|---|---|
| `L0` | 反射：可导入、有签名、async 标记一致、docstring 存在 | 只记 `OK`/`RAISED`，**不计入缺陷** |
| `L1` | **进程内**调用，参数按签名合成（默认值 → 类型占位符） | `risk=read` 全调；`llm` 在 mock 下可调（零成本）；`write` 允许（库里是临时数据根）；`danger` 不下探 |
| `L2` | **子进程**逐模块批跑（`python -m app.qa.probe --module X --batch`） | 60s 硬超时 → 抓 `hang` |

- 参数合成失败 → `SKIP` + reason，**不当成缺陷**；抛异常 → `RAISED` + traceback 首帧。
- 必须记录"每个异常是缺参（SKIP）还是真空指针/断言（RAISED）"的判据。

### 4.5 `cli_probe.py`（1129 行）—— CLI 与后台任务

| 验什么 | 怎么验 |
|---|---|
| 10 个子命令 | 各自独立数据根跑子进程，检查退出码与副作用 |
| 后台任务 | `mock 下不许启动`——这是独立断言，不是"没崩就算过" |

### 4.6 `coverage.py`（392 行）—— 真实函数覆盖

```python
class Tracer:
    def __enter__/__exit__      # 用 sys.monitoring(PY_START)，失败退回 sys.setprofile
    hits: dict[str, int]        # "module:qualname" -> 次数

def report(reg: Registry) -> dict   # {"covered": n, "total": n, "ratio": x, "uncovered": [...]}
```

- 只统计 `app.*` 的 code object；`vendor/` 另算（只读）。
- 必须能在同一进程里多次 `with Tracer()`。
- 口径：**只统计非 `SKIP` 的 fn/method**，所以 100% 永远见不到——这是有意的。

## 5. 双 AI 对抗（`duel.py` 1506 行 + `scenarios.py` 1601 行）

### 5.1 两个角色

| 角色 | 是什么 | offline | live |
|---|---|---|---|
| `Subject` | 被测对象，直接调 `loop.chat_turn` | `MockLLM`（`SYMEM_MOCK=1`） | 真 provider |
| `Prober` | "另一个 AI"，负责逼破绽 | 确定性模板（根据上一句选下一句） | 同一个 `rt.llm`，system 提示成"挑剔的测试用户" |

live 模式的硬约束：`--allow-live` 才允许；先查 `provider.is_mock` 决定是否降级；记录 token 与估算花费；超 `budget` 立即停。

### 5.2 场景契约（`scenarios.py`）

```python
SCENARIOS: list[dict]   # id/title/features/chat_type/uid/turns/goal/oracle_tags
```

| 字段 | 说明 |
|---|---|
| `id` | `S01`–`S50`（唯一，注册时前缀化成 `SCEN:S01`） |
| `features` | 该场景主要压到的模块（如 `loop.chat_turn`、`intimacy.gate.prepare`） |
| `chat_type` | `private` / `group` |
| `uid` | 固定 uid（`0` = 面板单用户线；`7001+` = QQ 多用户线，便于隔离断言） |
| `phase` | 关系阶段预设键（duel 用它预置好感） |
| `turns` | `offline_turns` 的别名，4–8 条脚本 |
| `goal` | live 模式给 Prober 的提示（也是 offline 的意图说明） |
| `oracle_tags` | 要判的规则：官方 5 个 `ooc` / `time` / `intimacy` / `memory` / `relation`，另加 `safety` / `style` |
| `expect` | `{max_latency_s: int, must_reply: bool}` |
| `preset` | 可选预置落库：`affinity / trust / attraction / aversion / lover(bool) / blocked(bool) / hour(int) / name_locked(bool)` |
| `driver` | `intimacy_gate`（调用方须先 `intimacy.gate.prepare`）/ `group_focus`（先写 kv `group_focus_user`） |

三个边界场景必须支持 `preset` 才跑得准：`S18`（79 分）、`S19`（81 分）、`S20`（bound_active + 冷却）。

### 5.3 一轮怎么跑

每轮：写 `TurnRecord`（latency、meta）→ 调 `oracle.check_turn` → 把 `Finding` 挂上去 → 转录落 `transcripts/{scenario}.jsonl`，prompt 快照落 `transcripts/{scenario}.prompt.json`（可关）。

## 7. 报告与判红（`report.py` 1272 行）

```python
def write(run_dir: pathlib.Path, *, registry, phases, findings, turns, meta) -> pathlib.Path
```

`report.md` 结构：总览（项数 / 通过 / 异常 / 跳过 / 覆盖 / 耗时 / 花费）→ 缺陷清单（按 `P0 → INFO`，带复现）→ 逐模块覆盖表（**列了没跑的单独一节**）→ 场景转录索引 → 环境与哈希。同时出 `report.json`。

判红门槛：

| 条件 | 结果 |
|---|---|
| 任何 `P0` | 退出码 1 |
| `NOTRUN > 0` | 视为失职（"列了没跑"） |
| `SKIP` 无 reason | 不合规 |
| `EXPECTED` | 不算红（负向用例通过） |

## 10. 改这一层要注意

1. **新增一个 phase 的接入点**：`types.PhaseResult` 产出 → 在 `scripts/adv_full.py` 的编排里注册 → 报告自动收。不要自己另写一套 dict。
2. **新增裁判规则**：往 `oracle.RULES` 里加 `Rule(id, severity, area, title, scope, requires)`，`id` 必须唯一；`scope` 只能是 `turn` / `scenario` / `state`。
3. **新增场景**：往 `scenarios.SCENARIOS` 加 dict，`id` 必须 `S##` 连续且唯一，`turns` 4–8 条。
4. **任何新模块都要能被 `inventory` 扫到**：它靠 AST 扫 `app/**/*.py`，所以放在 `app/` 下就自动进清单；**不要放在 `vendor/`**。
5. **禁止在 `app/qa/*` 模块顶层 import `app.core/app.mind/...`**——会绕过 `sandbox.prepare_env()`。
